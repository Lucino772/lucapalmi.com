A single migration history works well until two teams merge on the same day. Then you get two heads, a merge revision nobody really reviewed, and a chain that describes the order people pushed, not the shape of the system.

The fix I keep coming back to is boring: **let each module own its tables and its own history**. Each module gets its own version table, its own lineage, and it can only migrate what it owns.

```python
# each module declares what it owns
billing = Module("billing", tables=["invoices", "payments"])
accounts = Module("accounts", tables=["users", "sessions"])
```

<Callout type="tip">
    Placeholder tip used to design the callout styles: keep one version table
    per module so each lineage can be inspected on its own.
</Callout>

The trade-off is cross-module changes. They now need to be explicit, which is annoying, and also exactly the point: the boundary shows up in the tooling instead of only in a diagram.
